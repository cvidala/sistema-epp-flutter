# Quick Task 260823-t82: Fase 1 buckets privados — lecturas vía signed URLs

## Descripción

Primera de 4 fases para privar los buckets de Storage `evidencias` (foto de
entrega EPP + firma) y `fotos-rostro` (foto de perfil), hoy **públicos** y que
exponen rostros. Esta fase cambia **solo las lecturas** para usar signed URLs,
sin privar los buckets ni tocar escrituras — cero rotura.

## Contexto

Sale de una auditoría de datos sensibles. Plan por fases (sin downtime):
1. **Lecturas → signed URLs** (esta tarea)
2. Escrituras → guardar path
3. Backfill de filas existentes
4. Flip de buckets a privado (tras desplegar app en terreno)

## Tareas

1. **Helper Dart** `lib/services/storage_url_service.dart`: normaliza URL pública
   legacy / URL firmada / path y genera `createSignedUrl` (TTL 3600s), con
   fallback a la URL original si falla (bucket aún público).
2. **worker_detail_page.dart**: foto de evidencia y firma (vía `FutureBuilder`)
   y el `networkImage` del PDF resuelven signed URL antes de renderizar.
3. **dashboard/index.html**: helpers `extractStoragePath` / `signedStorageUrl` /
   `hydrateStorageMedia` + `abrirMediaFirmada`; migrar todos los `img/href` de
   `evidencia_foto_url`, `firma_url`, `foto_rostro_url` y `perfilUrl`
   (comprobante standalone resuelve antes de construir el HTML).

## Restricciones

- No privar buckets ni cambiar escrituras (fases 2-4).
- Mantener compatibilidad con datos legacy (URL completa).
- No tocar el bucket `asistencias-fotos` (ya usa signed URLs).

## Verificación

- `flutter analyze` sin issues en los archivos tocados.
- Sintaxis JS del dashboard válida (`node --check`).
- No quedan `img src`/`a href`/`window.open` con URL cruda de storage.
